# 完整样书与读者评估

本文件是评估协议，不是评估结果。当前没有完成真实模型样书盲评或读者测试，不宣称质量已验证。

## 固定任务

先做三本各 3–5 章的短书，固定模型、版本、配置、提示词和原型后运行：

| 样书 | 任务 | 重点 |
|---|---|---|
| 概念解释 | 为初学者解释概率、条件概率与常见误解 | 术语一致、例子和反例、读者理解 |
| 实践指南 | 为团队提供可执行的代码审查流程 | 操作完整性、失败情境、任务完成 |
| 证据综述 | 围绕一个范围明确的问题梳理公开研究 | 来源支持程度、时间范围、争议呈现 |

主题可根据作者实际需求替换，但单轮对比不能中途换题或换评分规则。

## 执行

1. 从已校验二进制运行 `--version` 并保存输出；记录 Provider、模型、配置、起止时间和样书目标。
2. 按 [入门](getting-started.md) 完成 new → expand → factcheck → revise → factcheck → review → finalize → export。保存每阶段副本，记录失败、重跑和人工干预。
3. 每本至少随机抽查 30 条论断（不足则全查）。审核人打开来源，标记支持/部分支持/不支持/来源失效，并记录来源原文位置。
4. 逐章检查术语冲突、必要前置知识、重复段落和无依据的具体数字；记录每千字人工修订分钟数。
5. 至少请 3 位符合目标受众的真实读者完成预设任务；使用阅读前后相同难度、不同题目的测验。记录匿名结果和失败原因，不把满意度当作学习效果。
6. 将 status 的已报告 Token 与 Provider 实际账单分别记录；搜索、阅读器与 embedding 费用单列。任何未知项填“未测量”。

## 决策规则

数据损坏、错误来源关联、静默跳过失败必须先修复。内容与学习效果的通过阈值由该书目标在运行前确定；首轮建立基线，不用事后调整阈值掩盖问题。下一轮只改一个主要因素，并保留前后产物与评分证据。
